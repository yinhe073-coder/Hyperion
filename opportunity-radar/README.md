# 机会雷达：自动找机会 → 快速验证 → 收钱 的工作流

一句话：**机器每天替你盯全网的需求信号并出一份日报，你每天花 10 分钟挑、每周花 48 小时验证 1 个，用真实付款来决定做不做。**

先说清楚边界：这套东西自动化的是「找线索」和「初筛」，这是最耗时间也最适合机器做的部分。
它不能保证赚钱——能不能赚到取决于第 3、4 步你是否真的去验证和成交。所有阈值都是经验值，按自己的数据调。

```
① 发现(自动,每天)  →  ② 筛选(自动 + 你 10 分钟)  →  ③ 48 小时验证(你)  →  ④ 收钱/放大(你)  →  ⑤ 周复盘(你 30 分钟)
      ↑                                                                                              │
      └──────────────────────── 根据复盘结果改 config.json（关键词、权重、画像）──────────────────────┘
```

## 5 分钟跑起来

```bash
cd opportunity-radar
node radar.js --dry     # 只打印不落盘，先看看效果（Node 20+，无需安装任何依赖）
node radar.js           # 生成 reports/日期.md，并记录已推荐过的信号
```

开启 AI 评估（强烈建议，见下文「为什么要开 AI 评估」）：

```bash
npm install
export ANTHROPIC_API_KEY=你的密钥
node radar.js
```

让它每天自动跑（GitHub Actions，免费）：

1. 把本目录和 `.github/workflows/opportunity-radar.yml` 合并到仓库的**默认分支**（定时任务只在默认分支上生效）。
2. 仓库 Settings → Secrets and variables → Actions，新增 `ANTHROPIC_API_KEY`（不加也能跑，只是退回规则打分）。
3. 仓库 Settings → Actions → General → Workflow permissions 选 Read and write。
4. 之后每天北京时间 08:17 自动运行：日报提交到 `reports/`，同时开一个 Issue，GitHub 会发邮件给你。也可以在 Actions 页面手动点 Run workflow。

## ① 发现：每天自动抓什么

| 来源 | 类型 | 为什么抓 |
|---|---|---|
| HN 评论里的 "I wish there was / I'd pay for / is there a tool…" | 需求 | 有人明说想要、甚至明说愿意付钱 |
| Ask HN 热帖 | 需求 | 一群人在讨论同一个没解决好的问题 |
| V2EX 热门/最新（按关键词过滤） | 需求 | 中文用户的求推荐、吐槽、求替代 |
| Show HN 高票 | 走红 | 已被市场投票验证的新产品 |
| GitHub 两周内 star 飙升的新仓库 | 走红 | 开发者正在追的新方向，可做周边/托管/教程 |
| Product Hunt 新品 | 走红 | 海外新品，可做中文版或更细分的版本 |

两类信号对应两种赚钱思路：

- **需求信号**：有人要、没人满足好 → 你来做。
- **走红信号**：别人已经验证有人要 → 你切更小的人群、做本地化、做配套工具或服务（不要原样照抄）。

想加来源：在 `sources.js` 里照着现有函数写一个，返回同样结构的数组，并加进 `collect` 的 `jobs` 即可。

## ② 筛选：自动打分 + 你每天 10 分钟

**规则打分**（`score.js`，无需密钥）：互动量、痛感词、付费词、与你技能的匹配度、新鲜度，五项加权，权重在 `config.json` 的 `weights`。
它只是粗筛，会混进闲聊帖，这是关键词方法的固有局限。

**AI 评估**（`llm.js`，可选）：把粗筛前 30 条交给 Claude，结合你在 `config.json` 里写的个人画像，
逐条给出 做/观察/放弃 的结论，以及：机会是什么、谁付钱、48 小时能做出的最小版本、今天的第一步、最大风险。
「放弃」的不会出现在日报里。每天一次调用，费用很低；模型可用环境变量 `RADAR_MODEL` 更换。

**你的 10 分钟**：打开日报，只问三个问题，三个都是「是」才进入第 3 步，同一时间最多验证 1 个：

1. 我能说出 3 个具体的、会为它付钱的人或公司类型吗？
2. 他们现在是不是已经在为这件事花钱或花大量时间？
3. 我能在 48 小时内做出一个能收钱或能收预订的东西吗？

务必把 `config.json` 里的 `profile.about` 和 `fitKeywords` 改成你自己的真实情况，这是筛选质量的最大杠杆。

## ③ 48 小时验证：先卖，再做

目标不是把产品做完，而是用最低成本拿到「有人愿意付钱」的证据。

| 时间 | 做什么 |
|---|---|
| 第 0–4 小时 | 写一页说明：给谁、解决什么、多少钱、怎么付（收款码/爱发电/Gumroad/预订表单皆可）。不写代码。 |
| 第 4–24 小时 | 去信号出现的原地方和 2 个同类社群发帖；私信 10–20 个表达过同样需求的人。回复原帖是转化最高的渠道。 |
| 第 24–44 小时 | 有人感兴趣才动手：用手工 + 脚本交付第一单（先人肉服务，后产品化）。 |
| 第 44–48 小时 | 按下面的标准下结论，在 `experiments.md` 记一行。 |

判定标准（经验值，可调）：

- **放大**：≥ 1 人实际付款，或 ≥ 5 人留下联系方式并明确问价。
- **调整一次再测**：有人回复感兴趣但没人问价 → 换人群或换定价，再给 48 小时，只此一次。
- **停**：触达 20 人以上仍无人回应 → 停，回到日报挑下一个。不要因为「已经做了一半」而继续。

## ④ 收钱与放大

验证通过后按这个顺序走，每一步都以收入为准：

1. **手工服务**：先人肉交付 3–5 单，摸清真实需求和愿付价格。
2. **半自动**：把重复劳动写成脚本，交付时间降下来，价格不降。
3. **产品化**：重复到第 5 单以上再做成自助产品（网页/插件/小程序/模板/数据订阅）。
4. **铺渠道**：把验证时有效的那个渠道做深，再加第二个；内容（教程、对比、案例）是最便宜的长期获客。

常见的变现形态（按启动难度从低到高）：代做服务 → 模板/脚本/数据包 → 付费教程/专栏 → 订阅工具 → 面向企业的定制。

## ⑤ 周复盘：每周日 30 分钟

只看 `experiments.md` 和本周日报，回答四个问题并据此改配置：

1. 本周日报里真正有价值的条目来自哪些来源、哪些关键词？→ 加强它们（`painPhrases`、`v2exKeywords`、权重）。
2. 哪些来源全是噪音？→ 删掉或收紧关键词。
3. 验证失败的共同原因是什么（没人群、没渠道、不愿付费）？→ 写进 `profile.about`，让 AI 评估以后避开。
4. 每小时投入的回报最高的是哪个实验？→ 下周时间优先给它。

## 文件说明

| 文件 | 作用 |
|---|---|
| `radar.js` | 主流程：采集 → 去重 → 打分 → AI 评估 → 写日报 |
| `sources.js` | 各数据源采集器 |
| `score.js` | 规则打分 |
| `llm.js` | 可选的 Claude 评估层 |
| `config.json` | 你的画像、关键词、权重、条数 |
| `data/seen.json` | 已推荐过的信号（60 天内不重复推荐） |
| `reports/` | 每日日报 |
| `experiments.md` | 验证实验台账 |
| `../.github/workflows/opportunity-radar.yml` | 每日定时任务 |

## 已知局限

- 不配置 AI 评估时，日报里会有不少无关帖子，只适合当素材池浏览。
- Reddit、小红书、知乎、即刻等来源需要登录或会拦截云端 IP，没有接入；有条件可在 `sources.js` 自行添加。
- 只抓公开接口、每天一次、每个来源几次请求，属于正常访问频率；请遵守各站点的使用条款，不要调高频率。
